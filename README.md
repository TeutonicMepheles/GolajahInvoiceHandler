# 发票报销管理助手

一个完全在本机运行的网页应用：以中国增值税发票、境外 Invoice 或 Receipt 作为报销条目的主文件，把消费截图、购入清单、支付记录等材料作为附件关联到对应主文件，再按金额规则检查材料、组合报销包并生成可打印的自适应横/竖版 A4 PDF 归档。

应用还提供独立的“报价测算”页签：输入合同金额上限、税率、管理费比例和大类条目数后，自动反算整洁的基础开发费用，并把税费及取整零散金额归入其他费用，使合同总额尽量贴近但不超过上限。

## 稳定入口

Windows 用户可下载 Release 中的 Windows ZIP，解压后双击 `Install-Windows.cmd`。需要预先安装 Python 3.12 并联网安装依赖；详见 [Windows 部署说明](docs/windows-deployment.md)。发布包不包含用户数据或密钥。

首次安装时，在 PowerShell 中进入本目录并运行：

```powershell
.\install.ps1
```

安装脚本会创建桌面和开始菜单入口，并把应用注册为当前用户登录后自动启动的后台服务。之后直接双击“发票报销管理助手”即可；入口会检查服务状态，必要时自动启动，再打开固定地址 `http://127.0.0.1:8765/`。

全新安装只会在目标数据目录严格为空时显式创建当前数据库结构。若已存在旧版数据库，安装脚本会保持服务停止并打印数据库 SHA-256 与迁移命令；先制作并验证完整恢复集，再按提示执行迁移，安装脚本不会静默升级已有业务数据。

如不安装后台入口，也可以运行 `.\start.ps1` 临时启动。需要移除后台入口时运行 `.\uninstall.ps1`；该操作不会删除业务数据。

## Codex / Hermes 本地 Agent

Windows 上可把应用显式注册为 Codex 或 Hermes 的本机 STDIO MCP。注册不会启动或停止网页服务，也不会由 `install.ps1` 自动执行：

```powershell
# 默认不授权读取本机文件，只暴露 15 个非文件工具
.\register-agents.ps1 -Agent all

# 显式授权固定本地目录后，暴露 17 个工具
.\register-agents.ps1 -Agent all -AllowedRoot "C:\Path\To\InvoiceFiles"

# 移除受管注册；不删除业务数据
.\register-agents.ps1 -Agent all -Remove
```

注册、移除或收窄授权目录后，关闭或刷新旧 Agent 会话并新建会话；旧 MCP 进程会因 registration lease 失效而拒绝新的业务调用。Codex 写工具使用 `writes` 风险审批；Hermes 当前受支持版本对每次非只读工具调用单独批准或拒绝。两者的审批都不能替代应用的实体版本、重复项核对和持久幂等检查。

后台任务、快捷方式和 Agent 注册配置都保存启动脚本及项目目录的绝对路径。项目目录移动、重命名或复制到新位置后，先从新位置重新运行 `install.ps1` 刷新应用入口，再运行 `register-agents.ps1` 刷新 Agent 注册并新建会话；不要继续使用指向旧目录的入口、会话或配置。

文件工具只接受授权目录内的绝对本地路径，不枚举目录，也不返回路径。发票导入及支付记录识别会在调用前显示以下披露并要求版本化确认：

> 若本地后端已配置识别凭据，此文件内容将发送至 DeepSeek 进行识别；未配置时仅保存为手工处理记录。

Agent 补齐“尚需附带”材料时不需要新命令：先用 `list_invoice_drafts` / `list_invoice_items` 定位 `material.complete=false` 的条目，再用 `get_invoice_item` 取得当前版本和 `material.missing`。其中 `foreign_payment_rmb` 与 `payment_record` 都使用 `add_invoice_attachment(category="payment_record")`，`purchase_list` 使用同名类别；若条目已在报销包内，还要传当前 `batch_ref.batch_version`。每次上传成功后必须再次调用 `get_invoice_item`，只使用新版本和新缺件结果继续，因为支付记录识别可能立刻更新人民币实付金额并新增购入清单要求。文件目标和条目目标都必须由用户明确指定，Agent 不猜测。

## DeepSeek 识别配置

识别功能只从后端环境变量读取密钥，密钥不会进入浏览器。项目使用 `.env.local`：

```text
DEEPSEEK_API_KEY=
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-v4-flash-vision-exp
```

不要把真实密钥提交到版本控制，也不要粘贴到前端设置页面。`deepseek-v4-flash-vision-exp` 是 DeepSeek 当前提供的实验性视觉模型；普通的 `deepseek-v4-flash` 和 `deepseek-v4-pro` 不接受图片。图片会直接发送给视觉模型，PDF 会先在本机逐页转换为 JPEG，再作为多张图片发送。

若 DeepSeek API 暂时不可用、余额不足或限流，导入副本仍会保存，应用会创建可手工补录的待确认草稿，不会丢单。设置页会显示密钥是否存在，以及最近一次实际识别是成功还是失败；未发起识别前不会为了探测状态产生额外调用。

## 数据位置

- 默认持久目录：`%LOCALAPPDATA%\InvoiceAssistant\data\`
- SQLite：`%LOCALAPPDATA%\InvoiceAssistant\data\invoice_assistant.sqlite3`
- 受管附件副本：`%LOCALAPPDATA%\InvoiceAssistant\data\imports\`
- 默认报销归档：`%LOCALAPPDATA%\InvoiceAssistant\data\archives\`
- 数据库快照：`%LOCALAPPDATA%\InvoiceAssistant\data\backups\`，自动与手工快照分别保留最近 30 份
- 30 天回收区：`%LOCALAPPDATA%\InvoiceAssistant\data\trash\`
- 报销包目录：包含规范命名的原始材料、`归档清单.json` 和合并 A4 PDF

全新持久目录严格为空时，显式迁移命令可把旧版 `data/` 内容复制到持久目录并修正附件、归档路径；原目录会保留为迁移安全副本。已有数据库的升级必须先停止全部写入口、制作并恢复演练一致恢复集，再使用数据库当前 SHA-256 运行：

```powershell
.\.venv\Scripts\python.exe -m invoice_assistant.migrate `
  --data-dir "$env:LOCALAPPDATA\InvoiceAssistant\data" `
  --expect-db-sha256 <当前数据库的 64 位 SHA-256>
```

生产升级按以下顺序执行：先停止计划任务及所有手工、MCP 写入口并确认 `127.0.0.1:8765` 已无监听；随后在数据根互斥锁保护下完成 SQLite 恢复日志归一化，保存完整数据目录、旧源代码、环境配置和离线依赖，并用旧版本在隔离路径恢复演练。恢复演练通过后再更新源代码和依赖；安装脚本发现旧 schema 时只报告在锁内计算的逻辑状态哈希并保持服务停止。使用该哈希显式运行上述迁移命令，重新运行安装脚本启动固定端口服务，检查 `/health`、存储协调状态并完成浏览器只读验收。只有这些检查通过后才重新运行 Agent 注册脚本；不要在迁移或验收之前启用外部写入口。

应用启动只做只读 schema 校验，不会隐式建库或升级。可在“设置”页面查看持久目录、手工创建数据库快照或修改归档根目录。导入成功后，删除文件原位置的副本不会影响应用内附件和后续 PDF。

## 主要流程

1. 在“录入中心”拖入图片/PDF，或手工新建条目。中国增值税发票、境外 Invoice 和 Receipt 会作为主文件草稿显示；购入清单、支付记录、消费截图及尚未分类的文件进入独立的“待关联附件”区域，不会与主文件平权进入确认流程。
2. 表格和卡片视图都会为每份主文件、待关联附件及已关联附件显示图片或 PDF 首页缩略图；缩略图标签和文件名下方优先显示发票、Invoice、Receipt、支付记录、购入清单等材料属性，不显示对整理报销帮助不大的文件大小。每份主凭据旁会清楚列出“尚需附带”的材料空槽。点击槽位本身只会把它选为粘贴目标，并显示“可按 Ctrl+V 粘贴对应材料”；只有精确点击槽内的“选择文件”按钮才会打开文件管理器，也可直接把文件拖入槽位。支付记录上传会先完成人民币实付识别并刷新列表，再提示识别金额；外币 Invoice/Receipt 因此会立即更新金额和材料规则，例如实付达到 1,000 元时刷新出购入清单空槽。每个缩略图都是预览按钮，点击后会在当前页面右侧停靠阅读器中打开图片或通过同源内嵌框阅读 PDF，不会下载文件或另开标签页。较窄窗口中阅读器会变为右侧覆盖层。把附件卡片拖到对应主文件卡片即可建立关联，也可使用目标选择器和按钮完成同一操作；无法识别的文件可先修正材料类型，再提升为主文件或关联为附件。若浏览器已载入新前端但本地后台仍是旧版本，录入中心会根据启动数据中的能力标识停用关联，并在阅读器内提示重启本地应用和刷新页面，避免把接口缺失显示成原始 404 错误。
3. 核对主文件的识别草稿并点击“确认进入待报销”。附件必须先关联到主文件，不能单独确认为报销条目。
4. 在“待报销条目”筛选并多选，创建本次报销。
5. 在工作区选择文件或直接拖放，继续补齐主凭据、购入清单和支付记录；外币 Invoice/Receipt 保留原币金额，但必须由支付记录确认人民币实付金额，报销合计与最终目录只使用该人民币金额。支付记录识别失败时可直接点击“重新识别人民币实付”，无需删除重传。缺件或外币实付未确认时导出会被阻止。用户确认过的附件名称会被锁定，导出时不会被自动覆盖。
6. 当前打开的处理中报销包可以作为固定合并目标，把同一项目下的其他处理中报销包并入其中。合并后保留当前目标的名称、项目、用途和备注，来源包的条目及附件进入同一工作区；若来源包曾从历史退回，其旧归档会移入 30 天回收区。旧归档路径暂时不可访问时会阻止合并并保留恢复引用。合并后的全部材料继续统一编辑、核对和导出。
7. 生成归档与自适应 A4 PDF：竖向材料使用 A4 竖版，横向材料使用 A4 横版并在保持比例的前提下铺满可用页面；报销包随后进入“已提交”。导出期间相关条目、附件和报销包被冻结，避免归档与数据库不一致。
8. 实际到账后在历史页面填写到账日期并标记为“已报销”。

## 删除与撤回

- 录入中心的表格和卡片视图都会把主文件草稿与待关联附件分区显示，并为每个文件提供可点击缩略图；图片与 PDF 都在当前页面右侧阅读器中预览。删除主文件草稿时，其已关联附件会一并进入清理流程；删除尚未关联的附件不会影响其他主文件。两类文件的受管副本都会先移入 30 天回收区，失败任务会持久记录并在后续启动时重试。
- 待报销条目支持单条或批量删除；删除记录时其受管附件同样先移入 30 天回收区。
- 处理中的报销包可以删除，其中条目会自动退回待报销池，不会删除附件。
- 已提交或已报销的历史记录需要输入完整报销包名称确认；可选择保留归档目录，或把 PDF 和归档材料一并移入 30 天回收区。
- 每个已提交或已报销的历史报销包都可以输入完整名称确认后退回编辑，不限于检测到数据异常的记录。新归档成功前该包的旧归档始终保留，成功后旧版进入回收区。
- 从历史退回的报销包也可作为处理中报销包继续管理；把它作为来源并入同项目的当前目标时，来源旧归档会立即进入 30 天回收区，而当前目标自己的旧归档仍保留到下一次成功导出。
- 每次删除、退回修正或合并报销包前都会自动创建数据库快照。数据库快照不包含附件内容，完整恢复时还应结合回收区或保留的归档目录。

## 报价测算

“报价测算”不写入报销数据库，可随时反复试算：

1. 输入合同金额上限，确认增值税率、附加税率和管理费比例。
2. 选择增值税口径：默认“含税价倒算”与既有报价单一致，也可切换为“按合同总额直接计提”。
3. 选择大类条目数及整百、整五百或整千的取整粒度。
4. 系统从金额上限向下搜索，优先得到整洁且均衡的基础开发费用，并展示税费、管理费及与上限的差额。
5. 在“基础开发费用明细”中直接修改条目名称，也可新增或删除顶层条目，并为任意条目添加子项目。顶层条目均衡分配全部基础费用，子项目均衡分配所属条目的金额；无法等分时允许不等额，但每项保持所选取整粒度且相邻金额最多相差一个取整单位，费用合计不变。
6. “说明列”默认关闭；点击“新增说明列”后，可为每个实际计价条目填写最多 1000 字的多行说明。拆分子项目时说明随实际计价行迁移，关闭后已填写内容仍会保留。
7. 点击“复制报价明细”，可把包含最新名称、层级、金额以及当前启用的说明内容粘贴到其他文档中继续编辑。
8. 点击“导出报价单.docx”，填写标题、需求方、项目负责人和日期后，系统会按照同济 AIGC 工具链报价单的表格格式生成 Word 文件，并保留末页联系信息与机构标志落款。未启用说明列时，Word 基础费用表仅保留“板块、项目、价格”三列；启用后导出“板块、项目、说明、价格”四列。导出前会校验基础费用、子项目、其他费用和合同总额是否一致。

默认 Word 模板位于 `invoice_assistant/templates/quotation_template.docx`。如需改用其他模板，可在 `.env.local` 中设置 `QUOTATION_TEMPLATE_PATH`；替代模板应保持相同的正文段落和三张表结构。

## 公开仓库数据边界

- 仓库中的名称、日期和金额测试值均为合成夹具，不来自真实发票或生产数据库。
- `.env*`（仅保留空值 `.env.example`）、`data/`、`work/`、`发票/`、SQLite、PDF、CSV 和本机工具配置均由 `.gitignore` 排除。
- 内置报价单模板为匿名通用模板，不含品牌、联系人、地址、邮箱、电话、真实金额、图片或个人文档元数据。
- API Key 只应保存在未跟踪的 `.env.local` 或后端环境变量中；提交前应再次执行秘密扫描。
